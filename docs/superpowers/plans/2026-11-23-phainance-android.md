# Phainance Android + Synced Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Phainance as a public free Android app (Play Store) that records UPI payments from notifications, and keep the web app in sync with it per account.

**Architecture:** Both clients are local-first: the React UI always talks to a local REST-emulating adapter (today's `guestAdapter`, generalised) backed by local storage (SQLCipher on Android, browser storage on web). A sync layer pushes/pulls changes to Spring Boot + Postgres by record UUID. A small Kotlin Capacitor plugin handles notification capture, widget/share target, and the encrypted native inbox that JS drains.

**Tech Stack:** React 18/Vite, Capacitor, Kotlin (NotificationListenerService, Room + SQLCipher, Glance), Spring Boot 3.2.1 / Java 21, Postgres, Flyway, JUnit 5, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-23-phainance-android-design.md`

## Global Constraints
- Money is stored as integer minor units (paise) plus a currency code; never `DOUBLE`.
- Database is Postgres; Flyway owns the schema; `DDL_AUTO=validate` by default.
- Auth: email + password and Google Sign-In; short-lived access token plus rotating refresh token; token subject is the user id, not the username; startup fails on the default `JWT_SECRET`.
- Device tokens live in Keystore-backed storage, never `localStorage`; web uses an httpOnly cookie.
- Local DB encrypted with SQLCipher, key held in Android Keystore; Android backup of app data disabled.
- Notification capture reads only an allow-list of packages; raw notification text is discarded after parsing; only debits become review items; nothing auto-captured becomes an expense without confirmation.
- Duplicate window: same UPI reference, else same amount within 10 minutes.
- No card storage, no SMS reading, no bank linking, no iOS in v1.
- Sync: idempotent by UUID, last-write-wins per record, tombstone deletes, only confirmed records reach the server.
- Hosting: free-tier host to start; server schedulers cannot assume an always-on instance.
- Existing suites (`mvn test`, `npm test`) stay green after every task.

## Review Focus
1. Refund, credit, OTP and promo notifications from allow-listed apps must not create review items (Task 14).
2. One payment announced by both the UPI app and the bank yields one review item (Task 16).
3. Amount formats `₹1,23,456.50`, `Rs. 500`, `INR 1,000.00` parse to exact paise (Task 14).
4. Edit-vs-delete on two devices, and replaying the same push batch, leave identical data (Tasks 6, 9).
5. Existing `DOUBLE` amounts (e.g. 0.1, 19.995, 1234567.89) migrate to paise without drift (Task 2).
